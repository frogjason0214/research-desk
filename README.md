# Research Desk

心理學研究輔助桌面工具（Windows）。目前完成第一階段（右側常駐邊欄、研究專案、論文里程碑與口試倒數、待辦清單、跨電腦同步、Google 行事曆、安裝檔與自動更新）與第二階段（文獻整理）。

## 安裝（給同學）

1. 到 https://github.com/frogjason0214/research-desk/releases 下載最新的 `ResearchDesk-Setup-x.y.z.exe` 並執行。
2. 安裝檔沒有數位簽章，Windows 會跳出「Windows 已保護您的電腦」：按「其他資訊」→「仍要執行」。
3. 之後有新版本時，程式會自動在背景下載，提示「重新啟動」即可更新。
4. 要使用 Google 行事曆，請先把你的 Gmail 告訴開發者，加入測試使用者名單。

## 發布新版本（開發者）

1. 把 `package.json` 的 `version` 往上加（例如 0.1.0 → 0.2.0），commit 並 push。
2. 在終端機設定 GitHub 權杖後執行 `npm run release`（權杖需要該 repo 的 Contents 讀寫權限）：

   ```
   $env:GH_TOKEN="github_pat_..."; npm run release
   ```

3. 已安裝的人下次開程式時會自動更新。

## 從原始碼執行（開發者，約 10 分鐘）

1. 到 https://nodejs.org 下載並安裝 **LTS 版本** 的 Node.js，安裝過程一路按「下一步」即可。
2. 把這個資料夾解壓縮到容易找的地方，例如 `文件\research-desk`。
3. 打開該資料夾，在空白處按右鍵 →「在終端機中開啟」（Windows 11）。Windows 10 可在資料夾網址列輸入 `powershell` 後按 Enter。
4. 輸入下列指令並按 Enter，第一次會下載套件，需要幾分鐘：

   ```
   npm install
   ```

5. 啟動程式：

   ```
   npm run dev
   ```

6. 第一次啟動不用做任何設定，資料會先存在這台電腦。想在多台電腦使用，再到「設定」開啟跨電腦同步。

之後每次要用，只要在同一個資料夾執行 `npm run dev`。只打包、不發布用 `npm run dist`，安裝檔會在 `dist\`。

## 怎麼用

- 螢幕最右側會出現一條細線，上面是距離學位口試的天數。滑鼠移過去就會展開邊欄，移開會自動收合。
- 邊欄右上角的 ⊙ 可固定展開，⤢ 開啟完整視窗。
- 完整視窗的「里程碑」頁可以填日期、勾選完成、調整順序；按「倒數」可指定邊欄倒數的里程碑。
- 完整視窗左側「文獻」：匯入 PDF（選檔或直接拖進頁面）或貼上網址加入網頁。英文文獻以 DOI 向 CrossRef 查書目；中文或沒有 DOI 的由 Gemini 判讀並標示「待確認」，核對後按「確認書目」。可一鍵複製 APA 第 7 版參考文獻與文中引用（貼到 Word 保留斜體）。研究類型、樣本、量表、主要發現由 AI 預填；勾「不送 AI」的文獻或筆記永遠不會送出。篩選框按 Enter 可搜尋全文。
- 「設定 → AI（Gemini）」填入自己的金鑰（https://aistudio.google.com/apikey 免費建立）；也可以關閉「匯入文獻時自動使用 AI」。
- 完整視窗左側「行事曆」：登入 Google 後以月／週檢視行程，點空白處新增、點行程修改或刪除。
- 有截止日的待辦會自動同步到 Google 的「研究任務」行事曆（全天事件；完成時標題加 ✓）。
- 「設定」頁可改專案名稱、開啟跨電腦同步、登入／登出 Google、設定開機自動啟動、結束程式。

## 資料存在哪裡

每個人的資料只存在自己的電腦或自己的雲端硬碟，不需要登入任何帳號。

- **預設**：存在這台電腦（`%APPDATA%\research-desk\library\`）。
- **跨電腦同步**：在「設定 → 資料與跨電腦同步」點選偵測到的 OneDrive／Google Drive／Dropbox（或「其他資料夾…」），程式會建立 `ResearchDesk` 資料夾並把資料搬過去。另一台電腦在設定裡選同一個雲端硬碟就能加入。
- 兩台電腦可以同時開著、同時編輯，不會被鎖成唯讀。

| 位置 | 內容 |
| --- | --- |
| `ResearchDesk\changes\<裝置編號>.jsonl` | 每台電腦各自的變更紀錄，只有那台電腦會寫入 |
| `ResearchDesk\files\papers\` | 文獻檔案：`<id>.pdf`、網頁正文快照 `<id>.html`、整頁快照 `<id>.mhtml`、全文 `<id>.txt` |

讀取時合併所有電腦的紀錄；兩台改到同一筆資料時以欄位為單位，最後修改的為準（用邏輯時鐘判斷，電腦時間不準也不影響）。因為每個檔案只有一台電腦寫入，雲端硬碟不會產生衝突副本。

- 雲端資料夾暫時找不到（OneDrive 登出、資料夾被搬走）時照常使用，畫面會提示，恢復後自動補上。
- 加入同步時，若雲端和這台電腦都有資料，會詢問要「合併」或「改用雲端的資料」（本機資料另存在 `library-backup-…` 備份資料夾）。
- 停止同步時，最新資料與檔案會複製回這台電腦，雲端那份不動。
- 舊版的 `research-desk.sqlite` 會在第一次啟動時自動轉換，舊檔改名為 `research-desk.sqlite.bak`。請把每台電腦都更新到新版，舊版程式不認得新格式。

## 程式結構

```
src/
  main/       主程式：視窗、變更紀錄與同步（library）、查詢快取（store）、處理畫面的請求
  preload/    畫面與主程式之間的安全橋接
  shared/     共用型別與里程碑範本
  renderer/   畫面（React）
    views/      邊欄 Sidebar、完整視窗 FullWindow
    components/ 倒數、待辦列、新增待辦等元件
```

想修改里程碑範本，編輯 `src/shared/types.ts` 最下方的 `MILESTONE_TEMPLATE`。

## 技術選擇備註

- 查詢使用 sql.js（WebAssembly 版 SQLite）的記憶體資料庫，由變更紀錄算出，不需要在 Windows 安裝 C++ 編譯工具。
- 寫進雲端的檔案都先寫暫存檔再改名，避免雲端硬碟同步到一半的檔案。
- 每 20 秒檢查一次其他電腦的修改；自己的修改約 2 秒後寫進雲端。

## Google 行事曆設定（開發者，只需一次）

1. Google Cloud Console 建立專案，啟用 Google Calendar API。
2. Google Auth Platform → 開始：目標對象選「外部」；在「目標對象 → 測試使用者」加入自己與同學的 Gmail（測試模式上限 100 人）。
3. Google Auth Platform → 用戶端 → 建立用戶端 →「電腦版應用程式」。
4. 把 `.env.example` 複製成 `.env`，填入用戶端 ID 與密碼，重新執行 `npm run dev` 或重新建置。

- 登入時權限畫面要勾選行事曆權限；沒勾的話 App 會提示重新登入。
- 測試模式的登入約 7 天過期，App 會在邊欄與完整視窗提示重新登入。
- 登入憑證以 Windows DPAPI 加密，只存在這台電腦（`google-token.bin`）；每台電腦各自登入。
- 待辦事件的 ID 由待辦 ID 算出（`rdt` + UUID），兩台電腦同時推送也只有一個事件。
